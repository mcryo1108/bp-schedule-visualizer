# Flooding / Serial BP Visualizer

元の `BP Decoder Visualizer` の符号、エラー生成、表示、パラメータを保ち、BPの更新方式を切り替えられるようにした版です。通常の符号格子を見るページと、回路レベルの detector error model (DEM) を見るページを分けています。

## 2つの可視化ページ

- `index.html`: 表面符号・カラー符号・古典LDPCの格子上でBPを可視化します。量子符号では、符号距離 `d` に対する保証訂正数 `t=floor((d-1)/2)` 以下に真のデータ誤り数を制限できます。指定重みのランダム生成と、1,000標本のシンドローム重み集計に対応します。
- `circuit-level.html`: 実際の `d=3, rounds=3, SI1000, p=0.001` 回路から生成したDEMを使います。測定ラウンドを3層に分けた3D表示をドラッグで回転、ホイールまたはピンチで拡大できます。変数ノードを直接クリックして複数の誤りをON/OFFにし、その検出事象、隣接候補、次数、事前・事後LLR、BP残差を追跡できます。次数1だけ、局所近傍、全420変数の表示を切り替えられます。

回路レベル側の「DEM変数1個」は、データ量子ビット上の誤り1個とは限りません。回路中の単一故障が生む検出事象の組を表すため、通常ページの保証訂正数による制限は回路レベルページにはそのまま適用していません。

表面符号に加えて、data qubitをハニカム格子の頂点、3色の面をparity checkとする三角形6.6.6カラー符号を選択できます。カラー符号の距離は `d=3,5,7` です。

## 更新方式

- フロッディング: 全チェックノードのメッセージを同時に更新し、その後に全変数ノードのメッセージを同時に更新します。`BP step` は半反復ずつ進みます。
- シリアル: 変数ノードを1個ずつ更新します。昇順、降順、スイープ開始前に生成するランダム順序から選べます。実際の更新順序は操作パネルに全件表示されます。先に処理した変数ノードの新しい `v→c` メッセージは、同じスイープ内の後続変数ノードが使います。`BP step` は全変数ノードを一巡更新し、ハード判定を行うまでを1 stepとします。LLR履歴も一巡ごとに記録します。

FloodingとSerialの自動実行速度は、1ステップを20 msごとに更新する標準モードと、1ステップを1 msごとに更新する最速モードから選べます。

更新方式を切り替えると、現在のエラーパターンを保持したままBPメッセージだけを初期化します。そのため、同じ入力に対する2方式の収束経路を比較できます。

全符号モードで変数ノードをクリックすると、そのノードの真のエラーを `0↔1` で反転できます。シンドロームは直ちに再計算され、BPメッセージは新しいエラーパターンに対して初期化されます。変数ノード以外の図領域をクリックすると、従来どおりBPを1ステップ進めます。

図領域の右上にある `図とLLRをコピー` を押すと、全符号モードでタナーグラフとLLR履歴を1枚のPNG画像としてクリップボードへコピーできます。そのまま資料やチャットへ貼り付けられます。

## ローカルで動かす

このフォルダで次を実行します。

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:4173/` を開きます。回路レベル版は `http://127.0.0.1:4173/circuit-level.html` です。

## 全ノードの計算記録（2026-10-23）

通常ページの全ノード・全更新について、両方向のメッセージ、事後LLR、参照した値の更新IDと時刻を記録します。検査更新ではシンドローム、tanhの各項、積、数値計算用の制限、新規計算値を残し、両方向のdampingでは以前の値も参照先として残します。計算式は元のsum-productのままです。

1. BP step または Run で計算します。選択中のノードに関係なく全ノードを記録します。
2. 数値を見るステップで時刻を選び、全ノードの計算記録から量子ビットまたは検査を選びます。
3. 受信・送信メッセージを押すと計算の内訳が開きます。参照先を押すと、実際に使った過去の値を遡れます。
4. 全記録を保存すると、格子・入力条件・全LLR履歴・全メッセージ・依存関係をJSONに保存します。記録を開くと保存時の履歴を閲覧できます。保存記録の閲覧中は計算を追加しません。

リセット・誤り配置変更・符号変更で現在の記録は新しくなるため、必要な記録はその前に保存してください。履歴はメモリに保持し、長時間・大きな符号では使用メモリが増えます。画面の数値は読みやすい桁数で表示し、計算元の詳細とJSONには元の値を保持します。全ビット表示のLLR縦軸も全履歴の値に合わせます。

記録は計算上の依存関係を示します。失敗の原因を自動判定する機能ではありません。

回帰確認は `node tests/regression.cjs` で実行します。シリアルの一巡単位の検証は `node tests/serial-step.cjs` で実行します。72条件で80ステップずつ、元の更新処理との数値の完全一致、参照値・更新計算、JSONの保存読込を確認します。

### BPアルゴリズムの比較

右側の「BPアルゴリズム」でサムプロダクトとミンサム（補正係数1）を切り替える。更新方式・シリアル順序の指定は独立。切替時には誤り配置と現在のシリアル順序を保ち、計算履歴を初期化するため、比較前に必要な全記録を保存する。

全ノードの計算記録で検査→変数メッセージを選ぶと、サムプロダクトでは各入力のtanh・積・制限後の積を、ミンサムでは各入力の符号・絶対値・最小値を与えた全入力を確認できる。どちらも送信先入力を除外し、dampingの混合を別表示する。次数1の検査では両方式とも既存の有限上限 `2*atanh(0.999999)` を使う。アルゴリズム名と計算過程は全記録JSONにも保存され、過去のアルゴリズム名のない記録はサムプロダクトとして読む。

検証：`node tests/regression.cjs`（従来サムプロダクトとの一致）、`node tests/min-sum.cjs`（符号・ゼロ・同値最小・次数1・damping・両更新方式）。

## ランダムserial BPの並列実行

各BPのLLR履歴では、線の近くにカーソルを合わせるとノード番号・sweep・記録されたLLRを表示します。クリックすると、全BPの同じノードの線と更新順序表を強調し、全ノード計算記録のBP・ノード・stepも連動します。キーボードでは線にフォーカスしてEnterまたはSpaceで選択できます。「強調を解除」で全ビット表示に戻ります。この操作では誤り配置や復号結果を変更しません。

シリアル更新・ランダム順序を選ぶと、並列数（1〜32）と最大反復数（1〜500）を指定して「ランダムBPを並列Run」を実行できます。各BPは独立したWeb Workerで、開始時の同じ符号・誤り配置・事前確率・damping・アルゴリズムを使い、互いに異なる固定ランダム順序で初期状態から計算します。1反復は全変数の1スイープで、シンドローム一致または最大反復数で終了します。実際のCPU同時実行数は端末とブラウザに依存します。

結果表には反復数と未充足数を表示し、「更新順序・LLR」を開くと各BPの全ビットLLR履歴を確認できます。個別の結果はJSONで保存できます。このJSONは並列比較用で、単体Runの全記録JSONとは異なります。並列実行では全メッセージの計算過程を記録しないため、単体Runとの実行時間の直接比較には使用しないでください。シンドローム一致は論理訂正の成功を保証しません。

`node tests/ensemble.cjs` で、4種類の符号・2種類のアルゴリズム・3種類のdampingについて、並列用計算と既存serial BPの各スイープの数値一致を確認できます。
